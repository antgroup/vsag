# GIST 长期 CRUD：退化曲线与同数据重建对照

本组 E13 回答“多少次增删改后开始退化”以及“是否仅由数据变化造成”。不是新算法优化，不覆盖 SIFT/Cohere、原生 Full 或所有生产场景。#2904 没有修改，原 E10/E11/E12 和历史原始数据不变。

## 实验怎么做

沿用 E12 的同一 Lite 生产库与输入：10000 条960维 GIST、1000查询行（998个不同向量）、CPU0/单线程、degree16、构建预算128、查询预算512、k10。每存储1个新进程，100轮×250循环。每循环是 Update 真改值→query→Remove→query→Add 新值→query；每轮存活数量回到10000。更新配方及 ID/供体顺序与 E12 完全相同。

每10轮做质量检查：0轮、10至100轮共11点。1轮对应750次修改API调用（250次Update、Remove、Add各一），另有750次混合查询；下面的“修改次数”不含查询或建库 Add。三个存储总计225000次修改、225000次混合查询、300对Save/Load、33个检查点。

每个点按当时的完整FP32输入向量计算FP64真值。同时 Create 一个新索引，用完全相同的当前向量和ID重新 Add/BuildGraph，比较“原地维护”和“当前数据重新建图”。不提高任何预算，不替换常驻原对象。重建在单线程 fork 子进程完成，父进程等待；子进程分配不改变父对象的分配器，但 fork/调度/缓存仍会扰动计时。

## 这些差距说明什么

FP32 初始0.9646，原地维护最终0.8888，同一批最终向量重建为0.9447。数据变化及新建图本身也会影响难度，不能把7.58个百分点下降全部归因为邻接修复；但同最终数据还有5.59个百分点的维护图／重建图差距，数据变化不足以解释全部下降。这里的维护历史包含更新、删除、重新插入、槽位顺序和选边等因素，还没有定位到某一条语句或一个函数的独立因果效应。

FP32 前10轮还略升，不能说从第一次删除起单调变差。20轮变化较小，30轮已有可见差距。本轮每10轮取样，只能定位区间，不能编造“恰好第某次操作开始失效”。原始包保留各点逐查询胜／负／平及5000次query-cluster bootstrap区间：按998个不同向量分组，重复query不当作独立样本。这是给定单次建图下的查询重采样，不是多次建图置信度，也不是新的项目质量门槛。

FP16 重建仍会重新编码当前向量；RaBitQ 重建还会重新训练模型。因此 RaBitQ 的差距不能单独解释为补边问题，也不能据此宣称量化模型没有影响。要继续用 only-Update、固定值Remove/Add和冻结模型等对照隔离。

## 内存、延迟与一致性

原始 `states.csv` 保留每轮持久化前RSS、父进程峰值、索引大小和线程数；`samples.csv` 保留每次修改／查询的wall、user/system CPU和调度计数。`curve.csv` 把它们与质量点对齐，并给出前10轮混合查询窗口的P50/P99。0轮没有这样的窗口，保留空值，不填假零。RSS包含输入、采样缓冲、索引及allocator保留，不是索引独占内存或容器capacity；子进程内存不在父进程RSS中，进程资源计时还可能包含子进程。不可与旧协议计时直接拼接，也不可把子进程诊断时延作为严格性能胜负。

300轮Save/Load均核对全部1000查询的有序ID和距离，共600000次额外搜索。三模式初末质量CSV与旧E12逐字节一致；全部300个快照hash/大小也与旧E12一致。说明这次诊断没有改变原有图演化，且在这些查询上显式快照恢复一致。曲线来自一直保留的内存对象，不是加载旧快照导致的下降。

这不代表每次修改自动落盘、原子文件替换、fsync或崩溃恢复；也不能证明所有可能查询／异常下都一致。当前无统一公开Shrink接口，局部容量回收不等于图质量恢复，RSS平稳也不证明零碎片。没有为本实验加入WAL、自动重建、生产图策略或新公共API。

## 复核与复现

新增检查点工具通过三存储默认模式／诊断模式快照及初末质量一致性回归，错误间隔、缺失点与损坏命中记录被拒绝；ASan/UBSan检查点回归通过。70项benchmark测试、Release5/5、社区51项、CMake契约、clang-format/clang-tidy15和官方双语文档检查通过。子进程使用`_exit`避免刷新继承的父进程流缓冲，不声称其退出泄漏检测完整覆盖。加入归档发布回归后，最终71项benchmark测试全部通过、无skip；最终规范版检查点工具也重新编译并通过ASan/UBSan回归。不把本地检查称作社区线上CI全部通过。未重新测整个Full／macOS／TSan或宣称新的生产代码覆盖率。

额外的独立benchmark C++ lint最初发现15个窄化转换／布尔转整数告警（包含旧工具代码），已用显式转换修正，没有禁用规则。原实测源码及失败日志保留；用相同编译命令重建实测版与最终规范版，两个完整可执行文件SHA256完全一致，并与测量时记录的binary hash一致；`.text`和`.rodata`也逐项相等。最终源码与原测量源码的区别明确记录，不冒充另跑了一轮长实验。

raw审计重算全部API计数／分位／质量交集／来源哈希与33个检查点，verify→pack→新目录unpack→verify通过。三个存储的33000个checkpoint查询状态的真值ID全部一致；另用独立NumPy FP64实现，重放更新配方，对预先指定10个query×11点、每点全部10000向量复算，110组Top10完全匹配。这是独立抽样复核，不冒充全部11000个真值查询的第二次穷举。
