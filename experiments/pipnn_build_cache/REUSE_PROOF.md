# PiPNN 最终邻接表复用：充分条件与验证范围

本研究只处理固定分区、旧节点 ID/构建 FP32 行不变、metric/维度/alpha/degree/tie 规则/投影矩阵不变的普通 fixed-alpha PiPNN。新增与删除允许存在；不覆盖内部 ID 重排、内容更新、重训练导致构建行变化、adaptive pruning、重复存储与正式 HGraph 路由层。

## 1. 依赖边界

叶内有向候选 u→v 会调用 insert_bidirectional，给 u 和 v 都投递候选。因此一个点的 reservoir 由其所有叶内出向和反向贡献共同决定，不能只检查自己的 Top-K。

robust_prune 的依赖则是局部的：源节点的 reservoir、候选向量、源距离键、alpha、最大度数、ID tie 规则。它不会读取别的节点的最终邻接表。因此在这些输入不变时，其他节点的图变化本身不要求当前节点重新剪枝。

## 2. 层次 A：入射候选流未变

对每个叶子，比较每个旧行与当前行的完整有序 (target, FP32 distance) 列表。列表变化、旧行删除或新行出现时，把该行 source 和旧/新列表全部 target 标记为 dirty。

未标记的存活旧节点：其所有入射投递事件均未变化。冻结叶次序、旧成员相对次序和 bidirectional 方向处理次序保留，未涉及该点的新增/删除事件不会改变其自身事件子序列。其方向 hash 和距离键也保持不变。

因此该点可以同时跳过 reservoir 重建与 robust_prune，直接恢复旧邻接表。重建 dirty 节点时，逐方向判断 dirty，不能简单丢弃“source clean”的整条无向投递。

本分类是保守的：某些变化候选本来会被 reservoir 拒绝，也会让端点被标记 dirty；不会因为这种保守性错误复用。

## 3. 层次 B：最终 reservoir 未变

对 dirty 节点按原顺序重新汇总候选。将新旧 reservoir 的完整 entry（target、hash、BF16 distance key）分别排序后逐项比较；不依靠 checksum 判定相等。

集合相同且旧向量、ID、参数不变时，robust_prune 排序后的候选次序与候选间距离相同，因此最终邻接表相同，可跳过剪枝。entry 的原存储顺序不要求相同，因为剪枝先按源距离和 ID tie 排序，每个目标在 reservoir 内唯一。

## 4. 层次 C：reservoir 已变，但可证明剪枝结果不变

记旧剪枝结果为按选择顺序排列的 S，旧 reservoir 为 C_old，新 reservoir 为 C_new。

必要前置检查：S 中每个目标都仍在 C_new，且它的 BF16 源距离键与旧值相同。缺失任何一个就回退完整剪枝。

只需额外检查 C_new 中原来不在 C_old 的 entry：

- 若 |S| 已达到 degree，且该候选在剪枝全序中排在 S 最后一个元素之后，旧选择过程在到达它之前已经停止，它不影响结果。
- 否则，必须存在一个在全序中早于该候选的 s∈S，满足原剪枝条件 alpha * distance(s, candidate) < source_distance(candidate)。这证明该新候选不会被选中。
- 找不到上述证据，就回退完整 robust_prune。缓存中的 source_distance 保持原 BF16 key 语义，不能换成未经量化的 FP32 源距离作判断。

为什么足够：按候选全序归纳，旧的已选节点仍按原次序保留；仍存在的旧拒绝候选可由原先更早的已选节点拒绝；新候选要么也被更早的旧已选节点拒绝，要么位于满额终止之后。删除旧拒绝候选不会改变选择状态。因而整个选择前缀不变。

前置检查中旧选中邻居仅仅“仍存活”是不够的：它们必须仍在当前 reservoir，且源距离键一致。新候选也不能只用源距离阈值一概忽略：旧 degree 未满时，末尾候选仍可能成为新增邻居。

## 5. 验证和计时

- 10k 派生数据 90%/95%/99% 对照三组，最终邻接表逐项一致。
- 9,000 组随机 reservoir 变更，覆盖零向量/重复向量/整数随机向量、alpha=1.0/1.2/1.5；证书接受 50 组，逐项与实际 robust_prune 核对，无错误接受。证书拒绝率高不是正确性失败，它允许保守回退。
- 同一 SIFT1M 派生输入上比较“增量叶内计算＋全合并全剪枝”与“增量叶内计算＋dirty 合并＋上述三层复用”。两侧均先物化当前叶候选以统一计时口径。
- 单线程下对 pair_distance 实际调用计数，包含证书检查和回退重剪枝。证书失败时已做的距离也计入，避免只报成功节省而隐去失败成本。

## 6. 缓存与工程代价

原型在内存中持有旧最终邻接、旧选中目标的源距离键，以及每节点旧 reservoir 的完整排序键。旧 reservoir 的固定 64×8-byte 槽位约 512 MB/1M 点；最终邻接和对应源距离键载荷上界约 192 MB（degree=32），还未计容器和索引。加上已有叶内快照，缓存可能超过 1.5 GB。

当前只是内存驻留研究原型，没有把新增最终状态序列化并重新读取，也没有定义正式 cache API。文件读取、压缩/解压、内容校验与缓存更新成本必须在产品判断前补测。该方案的复用比例不等于端到端收益，尤其 90% churn 场景检测和证书成本可能超过省下的剪枝。
