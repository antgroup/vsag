> 记录日期：2026-08-21

## 任务要求摘要

- 使用 3-5 个公开或项目已有数据集。
- 测试外层并发 `1 / 2 / 4 / 8 / 16 / 32`。
- 每个并发档位记录 QPS、P50、P99、召回率和扩展效率。
- 固定硬件、数据集、索引参数和搜索参数，进行多轮 baseline/candidate 对照。
- 中高并发 QPS 目标较基线提升至少 15%。
- 召回率变化不超过 1%，P99 延迟恶化不超过 10%。
- 若未达到目标，需要保留 profiling 证据和瓶颈分析。

任务原文见 `docs/2026-08-21-VSAG项目任务要求.md`。

### 构建环境

- CPU 环境：VSAG evaluator 报告为 AMD General Purpose，`32C121G`，调度亲和性为 64 个逻辑 CPU。

- 为绕过当前 GCC/第三方依赖的既有 warning-as-error 问题，构建时使用 `ENABLE_WERROR=OFF`；这不是源码修复。
- evaluator 可执行文件：`build-release/tools/eval/eval_performance`。

## 当前结论

- 3 个满足任务范围的数据集已下载并可被 VSAG evaluator 正常读取。
- 3 个 HGraph 索引均已成功构建。
- SIFT 的六档并发测试链路已跑通，所有查询成功且召回率稳定。
- 当前已有真实 baseline/candidate 的 SIFT 对照结果，但没有达到“QPS 提升至少 15%”的证据。
- 目前尚未运行 `perf`、火焰图、缓存未命中、内存带宽和线程争用分析。
- 真实 baseline/candidate 的 SIFT 五轮 A/B 已完成；当前优化在本机单 NUMA 环境下约有 3%-6% 的稳定 QPS 收益，但尚未达到 15% 验收目标。
- mutable 的 32 并发存在 P99 回归，immutable 模式下该回归消失；后续 profiling 应重点解释高并发调度、缓存和共享状态差异。

## 后续执行计划

1. 确定真正的 baseline 和 candidate 代码版本，禁止用同一构建副本代替正式 A/B。
2. 固定 CPU affinity、线程环境、CPU governor、索引参数、搜索参数和查询数量。
3. 对 SIFT、GloVe、NYTimes 至少各执行 5 轮 baseline/candidate 对照。
4. 每个数据集覆盖 `1 / 2 / 4 / 8 / 16 / 32` 并发，保留每轮原始 JSON、运行顺序和 SHA-256。
5. 用 `perf stat`、`perf record` 或等效工具采集 CPU 热点、缓存 miss、内存带宽和线程调度证据。
6. 根据 profiling 证据选择数据分块、padding、线程绑定、NUMA、批处理或调度方向中的至少一种进行优化。
7. 回归编译、单元测试、正确性测试和并发测试，再生成正式性能报告。
8. 将同样的真实 baseline/candidate A/B 扩展到 GloVe-100 和 NYTimes-256，确认收益是否依赖数据维度、距离类型或索引参数。
