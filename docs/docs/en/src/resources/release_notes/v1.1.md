# VSAG 1.1 Release Notes

## Compatibility

VSAG 1.1 removes the deprecated HNSW, FreshHNSW, and DiskANN index implementations. The names
`hnsw`, `fresh_hnsw`, and `diskann` are no longer registered by `Factory` or `Engine`; C++, C,
Python, Node.js, and `vsag_ext` creation attempts follow the existing unsupported-index path. The
C++ and extension APIs return `UNSUPPORTED_INDEX`, the C API returns `nullptr`, and language
bindings raise their corresponding exceptions.

This is a source and artifact compatibility break. The associated public index-name and parameter
constants, `IndexType` members, HNSW/DiskANN parameter helpers, and conjugate-graph-only
`Pretrain`/`Feedback` APIs have been removed. Existing HNSW or DiskANN BinarySet, ReaderSet, and
file artifacts cannot be loaded by VSAG 1.1 because deserialization requires creating the matching
index implementation first.

Because these public API removals are also binary-incompatible, shared libraries use a
major-and-minor SONAME and the installed CMake package requires the same major and minor version.
Applications must relink against VSAG 1.1 rather than loading it in place of VSAG 1.0.

The removed public helpers are `check_diskann_hnsw_build_parameters()`,
`check_diskann_hnsw_search_parameters()`, `generate_build_parameters()`, and
`estimate_search_time()`. They only generated or evaluated parameters for the removed legacy
indexes; there is no replacement auto-tuning API. Configure maintained indexes with their documented
build and search parameters. `Options::num_threads_io()` and `Options::set_num_threads_io()` are
also removed because the setting was consumed only by DiskANN.

Before upgrading, use VSAG 1.0 to read any required legacy artifact and rebuild it from the source
vectors and IDs with a maintained index. Use `hgraph` for general graph ANN workloads, `ivf` for
inverted-file workloads, or another index listed in [Creating an Index](../../guide/create_index.md).
Keep VSAG 1.0 available only where legacy artifact access is still required; the removed indexes
will not be restored or backported to earlier release branches.
